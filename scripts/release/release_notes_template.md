## Обновление

Выполняется на прод-сервере, из каталога проекта. Вариант C (корневой `docker-compose.yml`);
для вариантов A/B — те же команды со своим `-f` (см. DEPLOYMENT §9.1).

```bash
cd nexus

# 1. Сохранить текущие образы под версионным тегом — ОБЯЗАТЕЛЬНО ДО сборки.
#    Без этого `up --build` перетрёт nexus-*:latest, и откат превратится
#    в пересборку трёх образов (DEPLOYMENT §74.5).
./scripts/deploy/images.sh tag

# 2. (только если релиз добавляет миграции) дамп PostgreSQL — страховка отката.
#    Каталог deploy/arc исключён из git и из контекста сборки образов, поэтому
#    дамп не портит git status и не оседает в слое образа.
docker compose exec -T postgres pg_dump -U nexus nexus > deploy/arc/nexus_$(date +%F_%H%M).sql

# 3. Забрать тег и пересобрать сервисы.
git fetch --tags
git checkout v<новая>
git status --porcelain --untracked-files=no   # ДОЛЖНО быть пусто. Считаются только правки
                                            # отслеживаемых файлов: untracked версию не портят (§9.4)
docker compose up -d --build web receiver sender

# 3a. ТОЛЬКО если в разделе «Особое» сказано, что релиз меняет образ брокера
#     (§75 и подобные): отдельным шагом, в окне обновления — пересоздание
#     контейнера означает простой Kafka 30–60 с, requestAsync в это время
#     отвечает ошибкой. Команда шага 3 брокера НЕ касается.
docker compose up -d --build kafka
docker compose ps kafka          # ДОЛЖНО быть healthy

# 4. Проверить.
curl -s http://<host>:8000/api/version     # → {"version":"<новая>"}
curl -s http://<host>:8000/health
```

Миграции применяются автоматически на старте `web`/`receiver`; отдельный шаг не нужен.

## Откат

```bash
./scripts/deploy/images.sh list                 # какие версии сохранены на хосте
./scripts/deploy/images.sh rollback <прежняя> --apply
git fetch --tags && git checkout v<прежняя>     # привести дерево к откаченной версии
```

Схему БД откатывать **не нужно**: она обратно совместима, откаченный код стартует на ней и
сообщает об этом логом уровня `error` + метрикой `nexus_pg_schema_ahead=1`. Исключение —
релиз, который удалял или переименовывал колонку (тогда это сказано в разделе «Откат» выше):
там сперва `docker compose run --rm web --migrate-down N` **образом новой версии и до
пересборки**, затем откат кода. Подробности — DEPLOYMENT §10.
