# Доска сессий (session-board)

Порт `session-board` из проекта vika без привязки к ИБ 1С. Там доска была ключом по ИБ и
держалась на ручных объявлениях; здесь присутствие пишут хуки автоматически, а объявления —
дополнение.

Зачем: несколько сессий в одном рабочем дереве делят HEAD, индекс и файлы. 24.09.2026
`git switch -c` одной сессии увёл ветку другой, и та закоммитила свою фазу в чужую ветку
(см. память `feedback_shared_worktree_branch`).

## Команды

Скрипт: `.claude/skills/session-board/scripts/board.js` (Node, без зависимостей). Сессию
определяет по `CLAUDE_CODE_SESSION_ID` (он есть в Bash-туле), иначе `--as <id>`.

```bash
node .claude/skills/session-board/scripts/board.js show               # сессии, объявления, журнал (30 событий)
node .claude/skills/session-board/scripts/board.js show --tail 100 --all
node .claude/skills/session-board/scripts/board.js task "Phase 108.3: 499 вместо ERROR"   # моя задача (видна соседям)
node .claude/skills/session-board/scripts/board.js task ""            # снять задачу
node .claude/skills/session-board/scripts/board.js say "правлю internal/web/usecase/node.go, не трогайте" --hours 4
node .claude/skills/session-board/scripts/board.js clear              # снять свои объявления (--all — все)
```

Когда пользователь спрашивает, чем занята другая сессия, запускай `show` и пересказывай блок
«Сессии» и хвост журнала. В начале крупной задачи задай `task`: без неё соседи видят только
текст последнего запроса.

## Что делают хуки

Подключаются в `.claude/settings.local.json` (личный файл, в git не попадает), одна команда на
все события: `node "$CLAUDE_PROJECT_DIR/.claude/skills/session-board/scripts/board.js" hook`.

| Событие | Что пишет | Что показывает |
|---|---|---|
| `SessionStart` | старт, ветку; чистит сессии старше 7 дней | модели — свой id на доске и соседей; пользователю — строку, если в дереве уже кто-то работает |
| `UserPromptSubmit` | текст запроса (200 символов, секреты замаскированы) | соседей, только если у них что-то изменилось; новые объявления; смену ветки чужой рукой |
| `PreToolUse` (Bash, PowerShell) | — | **спрашивает пользователя** перед опасной git-операцией, если в том же рабочем дереве за последние 30 минут работала другая сессия; перед `git commit` напоминает сверить `git diff --cached --name-only` |
| `PostToolUse` (Edit, Write, NotebookEdit) | изменённый файл | предупреждение, если этот файл за последний час правила соседняя сессия |
| `PostToolUse` (Bash, PowerShell) | команду (160 символов, секреты замаскированы), свою смену ветки | смену ветки, если её сделала не эта команда |
| `SessionEnd` | конец сессии | — |

Опасные git-операции: `switch`, `checkout <что-то>`, `stash` (кроме `list`/`show`), `reset`,
`rebase`, `merge`, `pull`, `cherry-pick`, `am`, `restore` (кроме только `--staged`), `clean`,
`add -A/./-u`, `commit -a/--all/--amend`, `branch -m/-d/-D/-f`. Если соседей нет, хук молчит.

Хук никогда не валит сессию: любая ошибка пишется в `errors.log` каталога доски, выход 0.
Git не запускается: ветка читается из `.git/HEAD` (у worktree — из его gitdir).

## Где данные

`%LOCALAPPDATA%\claude-session-board\<путь-репозитория>-<хеш>\` (путь можно переопределить
через `SESSION_BOARD_DIR`, так гоняются проверки):

- `sessions/<session_id>.json` — присутствие: задача, запрос, ветка, до 20 файлов, 5 команд;
- `notes.jsonl` — объявления со сроком (`--hours`, по умолчанию 12);
- `events.jsonl` — журнал, при 1 МБ ротируется в `events.1.jsonl`;
- `errors.log` — ошибки хука.

Ключ доски — основной git-каталог, поэтому сессии в `git worktree` этого репозитория видят друг
друга. Вопрос про git-операции задаётся только соседям из того же рабочего дерева: у worktree
свои HEAD и индекс.

## Границы

- Видны только сессии с подключёнными хуками. Сессия, запущенная до подключения, появится на
  доске после перезапуска или после `/hooks`.
- Ручная смена ветки из терминала пользователя видна как «кто сменил, по доске не видно».
- «Активна» значит «действовала за 30 минут». Упавшая сессия без `SessionEnd` через 6 часов
  перестаёт попадать в подсказки, через 7 дней удаляется.
- Секреты маскируются по шаблонам (Sentry, GitLab/GitHub, Telegram-боты, Bearer/Basic,
  `password=`, креды в URL, строки от 40 символов). Всё равно не вставляй секреты в запросы.
