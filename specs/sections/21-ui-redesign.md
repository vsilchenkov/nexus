## 21. Редизайн UI под эталон + API метрик панели

Реализовано в Phase 21 (блоки 21.1–21.6). Карта реализации с привязкой к коду —
в [../IMPLEMENTATION.md](../IMPLEMENTATION.md). Визуальный эталон всех экранов —
[../nexus_ui.html](../nexus_ui.html) (передаётся как референс компоновки; поведение,
валидация и контракты API — в §7 и здесь).

Назначение: привести весь веб-интерфейс (§7) к единому визуальному эталону
(тёмная тема, дизайн-токены, левый сайдбар + тонкий топбар), достроить
структурные части, которых не было (вкладки узла, KPI, графики, переключатель
таблица/карточки), оформить поздние разделы (Teams §18, Notifications §20, тема)
в том же стиле и добавить отсутствовавший **HTTP-API метрик** для дашбордов.

`nexus_ui.html` фиксирует **внешний вид и компоновку**; этот раздел — требования
к реализации; §7 — поведение экранов; §6 — сами Prometheus-метрики.

### 21.1 Дизайн-система

- **Токены** — единый источник в `web-ui/src/styles/globals.css` (CSS-переменные,
  цвета как `r g b` для opacity) и `web-ui/tailwind.config.js`. Перенесены из блока
  `:root` эталона: поверхности (`--bg-app/--bg/--bg-muted/--bg-3`), текст
  (`--fg/--fg-muted/--fg-subtle`), границы (`--line/--line-strong`), семантика
  (`--accent/--ok/--warn/--err`), радиусы (`sm/md/lg`), шрифты.
- **Тема** — тёмная основная; светлая описана зеркально теми же токенами. Класс
  `dark` на `<html>`, хранение в `localStorage` (`nexus.theme`), применяется до
  первого render. Переключатель — иконка в топбаре (отдельной страницы настроек
  темы нет).
- **Шрифты** — Inter (sans) + JetBrains Mono (mono), подключаются ссылкой в
  `index.html`; при отсутствии сети — graceful fallback на системный стек.
- **Иконки** — lucide-react (имена близки к Tabler из эталона).
- **UI-kit** — `web-ui/src/components/ui/*`: `Button`, `Input/Select/Textarea/Field`,
  `Card`, `SectionHead`, `Modal`, `Chip`, `Pill`, `Kpi/KpiRow`, `Seg`, `Hint`,
  `PickGroup`, `Toggle3`, `TrafficChart`. Атомы — единый источник внешнего вида;
  экраны собираются из них.

### 21.2 App-shell

- Постоянный **левый сайдбар** (`Sidebar`): бренд-лого, разделы `Узлы` / `Audit log`
  / `Настройки`, футер с текущим пользователем и ролью.
- **Тонкий топбар** (`Topbar`): хлебные крошки слева; справа — переключатель команды
  (multi-tenancy, §18), переключатели языка и темы, выход.
- `AppShell` композитит сайдбар + топбар + прокручиваемый контент; защищённые
  маршруты — layout-route через `<Outlet/>`. Login — вне shell.
- **Отклонение от эталона (согласовано):** пункты настроек не висят в главном
  сайдбаре по отдельности — есть один пункт `Настройки`, ведущий на подстраницу с
  собственным вложенным меню (ClickHouse, Пользователи, API Tokens, Sentry, Язык +
  поздние Teams, Notifications).

### 21.3 API метрик панели

Web Service опрашивает Prometheus и агрегирует ClickHouse; раньше HTTP-API метрик
не было (§6 описывает только эмиссию метрик сервисами).

- **Эндпоинты** (read-only, scope `metrics:read` для API-токенов):
  - `GET /api/metrics/overview` — глобальные KPI за 24ч: входящие, исходящие,
    очередь Kafka, ошибки + error_rate; флаг `prometheus_available`.
  - `GET /api/metrics/nodes?range=15m|1h|24h|7d` — per-node throughput (in/out/errors),
    ключ — `node` = path узла.
  - `GET /api/metrics/nodes/{id}?range=…` — KPI узла (total/delivered/p95/p99/errors)
    и временной ряд для графика; флаг `chart_available`.
- **Источники:**
  - *Prometheus* (`prometheus.url` в конфиге, §8) — глобальные KPI (`increase(
    nexus_requests_total{service="receiver|sender"})`), очередь (`sum(nexus_kafka_lag)`),
    per-node throughput (`sum by (node)`). Это query API сервера Prometheus, не
    scrape-эндпоинт `/metrics` сервисов.
  - *ClickHouse* — точные перцентили `quantile(0.95/0.99)(duration)` и
    счётчики/ряд по таблице логов узла.
- **Деградация (обязательна):** пустой `prometheus.url` → провайдер не создаётся,
  ответы отдают нули с `prometheus_available=false` (UI скрывает KPI/очередь/график);
  узел без `clickhouse_table` → `chart_available=false`. Никаких 500 — поллинг UI не
  должен спамить ошибками.
- **Деплой:** Prometheus становится зависимостью Web для дашбордов (см. DEPLOYMENT.md,
  DEVELOPMENT.md). Без него остальная панель (узлы, логи, настройки, audit) работает.

### 21.4 Экраны (привязка к §7)

Все экраны §7 приведены к эталону на UI-kit:

- **Login (§7.1)** — центрированная карточка с лого-градиентом.
- **Overview (§7.3)** — 4 KPI (из `/api/metrics/overview`), поиск, фильтр по методу,
  переключатель **Таблица/Карточки** (выбор в `localStorage`), колонки Вход 1ч /
  Выход 1ч / Ошибки и производный статус-pill (OK / Очередь / Down) из
  `/api/metrics/nodes`.
- **Node detail (§7.4)** — вкладки **Обзор / Логи / Конфигурация / Метрики**: Обзор —
  KPI узла + график трафика + последние запросы; Логи — live-tail/SSE с фильтрами и
  replay; Конфигурация — read-only сводка; Метрики — перцентили + график за диапазон.
- **Replay (§7.4.1)**, **Dry-run (§7.5.1)** — в общем компоненте `Modal`.
- **Node settings (§7.5)** — двухколоночная форма (5 секций + предпросмотр маршрута)
  на `PickGroup/Toggle3/Field/Hint`.
- **Удаление узла (§7.5)** — диалог с чекбоксом «также удалить таблицу логов» (по
  умолчанию выкл; дроп — вторым вызовом orphan-эндпоинта) и подтверждением вводом path.
- **Создание CH-таблицы (§7.6)** — реализовано через шаблоны (§19): селектор шаблона
  в форме узла + панель шаблонов в настройках (таблица создаётся автоматически).
- **Settings → ClickHouse (§7.8)**, **Users (§7.9/§7.10)**, **Language (§7.11)**,
  **Audit log (§7.13)**, **API Tokens (§7.14)** — на UI-kit и палитре эталона.

### 21.5 Поздние разделы в едином стиле

В эталоне их нет; оформлены тем же UI-kit на подстранице «Настройки»:

- **Teams (§18)** — управление командами и участниками; переключатель команды — в
  топбаре.
- **Notifications (§20)** — настройки Telegram-уведомлений.
- **Тема** — отдельная страница убрана; переключатель тёмная/светлая перенесён в
  топбар.

### 21.6 Неочевидности

- KPI/очередь/графики деградируют без Prometheus; per-node KPI/перцентили на странице
  узла продолжают работать из ClickHouse (узел с таблицей).
- Производный статус узла (OK/Очередь/Down) — эвристика на фронте: учитывает
  `node.status`, долю ошибок и для `requestAsync` — отставание выхода от входа.
- Встроенный SPA (`internal/web/static`, embed.FS) пересобирается `make build-ui`;
  выкладывается в конце редизайна, когда экраны готовы.
