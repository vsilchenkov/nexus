## 2. Архитектура верхнего уровня

Два независимо разворачиваемых сервиса:

- **Receiver Service** — публичный HTTP-вход, валидация, авторизация входящих запросов, выбор узла по конфигу, передача в Sender Service по gRPC, формирование ответа клиенту.
- **Sender Service** — внутренний сервис доставки: gRPC-сервер для синхронных вызовов, Kafka-consumer для асинхронных, HTTP-клиент к внешним узлам.

Зависимости: PostgreSQL (конфиг — источник правды), Redis (горячий кеш конфига и сессий), ClickHouse (логи), Kafka (асинхронная очередь), Prometheus (метрики), отдельный сервис веб-UI (Go + любой современный фронтенд-стек).

Всё разворачивается через `docker compose` одной командой; одновременно поддерживается локальный запуск без Docker (для разработки).
