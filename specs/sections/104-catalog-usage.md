# 104. Узлы, использующие элемент справочника

Раздел превращает счётчик «узлов: N» в трёх справочниках Настроек («Разрешённые хосты» §23,
«Заголовки» §24, «Группы» §99) в кнопку, которая открывает список этих узлов. Повод: справочники
общие на инсталляцию, а в Настройках видно только число. Кнопка удаления у используемого элемента
заблокирована, и выяснить, кто её блокирует, можно только перебором всех узлов всех команд.

Развивает [§23](23-allowed-hosts-catalog.md), [§24](24-headers-catalog.md),
[§99](99-node-groups.md) (справочники и их `usage_count`), [§62](62-global-node-search.md) и
[§86](86-all-teams-scope.md) (видимость узлов по членствам: admin её не расширяет, §86.9),
[§100](100-click-targets.md) (строка со ссылкой — настоящая ссылка).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md). **Миграций раздел не требует.**

---

## 104.1 Назначение и scope

**В scope:**

- список узлов, ссылающихся на элемент справочника, в диалоге из Настроек — для хостов, заголовков
  и групп;
- видимость по членствам: узлы своих команд — со ссылками, узлы чужих команд — только числом;
- пометка «не действует» у привязки хоста к узлу, где хост не проверяется;
- актуальность счётчиков Настроек после правок узлов.

**Вне scope:**

- действия из диалога (отвязать хост, убрать узел из группы, снять заголовок) — список только для
  чтения, правка остаётся в форме узла;
- справочник полей запроса (`request_fields_catalog`): у него нет вкладки в Настройках. Бэкенд
  подключает его новой записью без правки usecase (§104.4);
- автоотвязка хоста при переводе узла в статический URL;
- поиск по диалогу сверх фильтра по пути среди загруженных строк.

## 104.2 Что значит «узел использует элемент»

Предикат один и тот же для счётчика в таблице и для списка. Он вынесен в константу рядом со
счётчиком, и из неё строятся оба запроса:

| Справочник | Связь | Предикат (узел `n`) |
|---|---|---|
| Группы (§99) | `nodes.group_id` → FK | `n.group_id = node_groups.id` |
| Заголовки (§24) | имя строкой в `nodes.forward_headers` | `EXISTS (SELECT 1 FROM unnest(n.forward_headers) fh WHERE lower(fh) = lower(headers_catalog.name))` |
| Хосты (§23) | таблица-связка `node_allowed_hosts` | `EXISTS (SELECT 1 FROM node_allowed_hosts nah WHERE nah.node_id = n.id AND nah.host_id = host_allowlist.id)` |

У хостов `usage_count` хранится в колонке и ведётся триггером на `node_allowed_hosts`. Список
считает по той же таблице, поэтому число и список совпадают по построению.

## 104.3 API

Три маршрута, по одному на справочник:

| Endpoint | Доступ |
|---|---|
| `GET /api/node-groups/{id}/nodes` | любая сессия (`RequireSessionOnly`) |
| `GET /api/headers/{id}/nodes` | любая сессия |
| `GET /api/allowed-hosts/{id}/nodes` | любая сессия |

Ответ:

```json
{
  "items": [
    { "id": "<uuid>", "path": "1c/orders", "target_url": "https://…",
      "url_mode": "static", "root_method": "request", "status": "enabled",
      "team_id": "<uuid>", "team_slug": "logistics", "team_name": "Логистика" }
  ],
  "total": 7,
  "visible": 5,
  "hidden": 2
}
```

- `total` — узлы **всех** команд, тем же предикатом, что `usage_count` (§104.2).
- `visible` — узлы в командах, где пользователь состоит.
- `hidden = max(0, total − visible)` — узлы чужих команд. Отдаётся только числом, без путей и id.
- `items` — видимые узлы, не больше 500, `ORDER BY path, id`. При `visible > len(items)` список
  усечён.
- Нет элемента, или `id` не UUID → `404` с существующими ключами `node_group.not_found`,
  `header.not_found`, `host.not_found`.
- **Только сессия.** API-токен закреплён за одной командой, а выдача строится по членствам
  пользователя — та же логика, что у `/api/search/nodes` (§62) и `scope=all` (§86). По токену `403`.
- **Любая роль.** `usage_count` и так отдают `GET` справочников любой сессии, поэтому `hidden`
  нового не раскрывает. Пути и id узлов чужих команд за пределы SQL не выходят.

## 104.4 Устройство

- **Отдельный порт `CatalogNodeLister`**, а не новые поля в `ListNodesFilter`. Фейки `NodeRepo`
  в unit-тестах фильтр не читают, и тест usecase зеленел бы, даже забудь usecase выставить фильтр.
  `List` расшифровывает креды каждой строки, а диалогу нужны семь полей. И главное: пустой
  `TeamIDs` в `ListNodesFilter` означает «одна команда из `TeamID`», а здесь пустой скоуп обязан
  означать «видимых нет» (fail-closed).
- **Один SQL-оператор на ответ.** Существование элемента, `total`, `visible` и строки списка
  берутся из одного снимка: `count(...) FILTER (WHERE n.team_id = ANY(...))` для чисел и
  `LEFT JOIN LATERAL … LIMIT` для строк. `hidden` поэтому согласован со списком, а не посчитан из
  двух запросов в разные моменты. Синтаксис совместим с PostgreSQL 12.
- **Usecase знает только вид справочника.** Он держит карту «вид → lister» (group, header, host),
  резолвит членства через `teamScope` (§86.2) и обогащает строки слогом и именем команды.
  Четвёртый справочник подключается новой записью в карте и новым предикатом, без правки usecase.

## 104.5 Интерфейс

**Таблица справочника.** «узлов: N» становится кнопкой в стиле ссылки (`aria-haspopup="dialog"`),
«не используется» остаётся текстом. У заблокированной кнопки удаления подсказка дополнена: «нажмите
на число узлов, чтобы увидеть какие».

```
Настройки → Группы (так же Заголовки, Разрешённые хосты)
│ ИМЯ        │ ОПИСАНИЕ        │ УЗЛОВ            │
│ 1С Обмен   │ Интеграции 1С   │ [узлов: 7]  ✎ 🗑 │ ← кнопка, открывает диалог
│ Резерв     │ —               │ не используется  │ ← текст
```

**Диалог.**

```
┌ Узлы группы «1С Обмен» ───────────────────────────────── ✕ ┐
│ Всего узлов: 7 · в ваших командах: 5                       │
│ [🔍 Фильтр по пути…]              ← только если строк > 8   │
│ 1c/orders          [request] [Активен]         [Логистика] │ ← вся строка — ссылка
│ https://1c.example/api/orders  [не действует]              │ ← только хосты, url_mode = static
│ 1c/stock      [requestAsync] [Пауза]           [Склад]     │
│ URL из запроса                                             │
│ ⓘ Ещё 2 узла в командах, где вас нет                       │
├────────────────────────────────────────────────────────────┤
│          [Показать на рабочем столе]  [Закрыть]            │ ← первая — только группы
└────────────────────────────────────────────────────────────┘
```

| Состояние | Что показано |
|---|---|
| загрузка | «Загрузка…» |
| `visible = 0`, `hidden > 0` | «Все N узлов — в командах, где вас нет», списка нет |
| `hidden > 0` | строка «Ещё K узлов в командах, где вас нет» под списком |
| `visible > len(items)` | «Показаны первые 500 из M» |
| `total = 0` | «Элемент больше не используется узлами» (счётчик устарел — таблица обновляется) |
| 404 | «Элемент удалён», таблица справочника обновляется |

- **Строка — настоящая ссылка** `/nodes/{id}` на всю ширину (§100): Ctrl+клик, средняя кнопка и
  «Открыть в новой вкладке» работают. Команду сессии переключает страница узла (§58).
- **«Не действует»** — только в диалоге хоста, у узла с `url_mode ≠ from_request`. Receiver
  проверяет allowlist только при URL из запроса, поэтому такая привязка ничего не разрешает и не
  запрещает, но блокирует удаление паттерна. В форме узла её не видно: поле хостов показывается
  только в режиме «URL из запроса». Подсказка к бейджу говорит, как её снять: временно включить
  «URL из запроса» и отвязать хост.
- **«Показать на рабочем столе»** — только у групп: ссылка `/?team=*&group=<id>` открывает экран
  «Узлы» в сквозном режиме §86 с фильтром по группе §99.5. У заголовков и хостов такого фильтра нет.
- **Фильтр по пути** появляется, только если строк больше восьми, и фильтрует загруженные строки.

## 104.6 Неочевидности

- **Счётчик в таблице и список в диалоге могут разойтись на время.** Таблица справочника
  кешируется (до 30 с), список запрашивается при каждом открытии. Если `total` из ответа не
  совпал с числом в строке, диалог сбрасывает кеш списка справочника, и счётчик в таблице
  подтягивается сам. Защита от удаления от этого не зависит: её держат сервер и СУБД (§23, §24,
  §99).
- **Счётчики отставали и до этого раздела.** Привязка и отвязка хоста в форме узла, сохранение,
  удаление и копирование узла меняют `usage_count`, но кеш справочников не сбрасывали. Теперь
  сбрасывают вместе с кешем диалога.
- **Пустые членства — не ошибка.** Пользователь без команд получает `visible = 0` и честный
  `hidden = total`. Запрос с пустым набором команд до SQL доходит, потому что нужен `total` и
  ответ 404 для несуществующего элемента, но по построению (`= ANY('{}')`) не видит ни одного
  узла.
- **`hidden` считается от `visible`, а не от длины списка.** При усечении до 500 строк разность
  с длиной списка приписала бы видимые узлы чужим командам.
- **Esc в поле фильтра закрывает весь диалог** — общий обработчик `Modal`. Это приемлемо: фильтр
  одноразовый.

## 104.7 Проверка результата

- у группы с узлами в своей и чужой команде диалог показывает свои узлы и «ещё K»;
- `total` ответа совпадает с `usage_count` таблицы для всех трёх справочников;
- заголовок, записанный в узле в другом регистре, считается и показывается;
- узел в статическом режиме с привязанным хостом виден с бейджем «не действует»;
- строка диалога открывается Ctrl+кликом в новой вкладке;
- после привязки хоста в форме узла счётчик в Настройках обновлён без ожидания;
- API-токен получает 403; несуществующий или не-UUID `id` — 404.
