# 63. Автор создания и последнего изменения узла

Раздел добавляет в инфо-вкладку узла («Конфиг») сведения о том, **кто** создал и кто последним
изменил узел: строку «Создано» с логином создателя и строку «Обновлено» с логином редактора.
Развивает §21 (UI-kit, вкладка «Конфиг»), §26 (RBAC/актор), §59 (read-only поля ConfigTab).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md).

## 63.1 Проблема

Во вкладке «Конфиг» узла ([ConfigTab.tsx](../../web-ui/src/components/node/ConfigTab.tsx)) показывалась
только дата «Обновлено», но не было видно, **кто** менял узел. Оператору при разборе инцидента важно
знать автора последней правки (и создателя).

## 63.2 Модель данных

Две колонки-логина в таблице `nodes` (миграция 0026), по образцу
`node_allowed_hosts.created_by`/`headers_catalog.created_by`/`request_fields_catalog.created_by`:

```sql
ALTER TABLE nodes ADD COLUMN created_by VARCHAR(255) NOT NULL DEFAULT '';
ALTER TABLE nodes ADD COLUMN updated_by VARCHAR(255) NOT NULL DEFAULT '';
```

- **`created_by`** — логин создателя, пишется при `Create`/`Copy`, дальше не меняется.
- **`updated_by`** — логин последнего редактора, пишется в тех же UPDATE/INSERT, что бампают
  `updated_at`: `Update`, `SetStatus` (пауза/отключение), `Move`, снимок allowlist-хостов.
- **Почему колонка, а не аудит-лог.** Аудит хранит логин денормализованно и уже фильтруется по узлу,
  но: (1) его чистит retention → у давно не менявшегося узла автор бы исчез; (2) `/api/audit` доступен
  только operator+ (на момент §63 — manager+), а инфо узла видят и `viewer`; (3) потребовался бы доп. запрос на каждый `Get` узла.
  Колонка `updated_by` пишется в лад с `updated_at`, поэтому автор всегда соответствует показанной дате,
  виден всем ролям (часть `NodeResponse`, логин — не секрет, как `auth_login`) и не зависит от аудита.
- **Автор — из `Actor.UserLogin`** (уже приходит во все мутации через `actorFromCtx`). При отсутствии
  логина в сессии — пусто.
- **Без бэкфилла:** у узлов, созданных до миграции 0026, обе колонки пусты (в UI подпись «Автор»
  не выводится вовсе — остаётся только дата);
  заполнятся при следующем сохранении/смене статуса.

## 63.3 UI (вкладка «Конфиг»)

- Строка **«Создано»** ВЫШЕ «Обновлено»: `<дата>` + `· Автор: <логин>` (моноширинный). Если автор
  пуст — подпись «Автор» **не выводится** (только дата), чтобы не зашумлять строку пустым значением.
  Показывается **всегда**.
- Строка **«Обновлено»**: `<дата>` + `· Автор: <логин>`. Показывается **только если узел меняли**
  после создания — критерий `updated_at !== created_at`. При создании оба таймстемпа получают один
  `now()` транзакции (в т.ч. при копировании — снимок allowlist идёт в той же UoW-транзакции), поэтому
  строки идентичны и «Обновлено» скрыто, пока узел реально не изменят.
- Хелпер `DateWithAuthor` в ConfigTab; i18n `common.created_at`/`common.author` (ru/en),
  `common.updated_at` уже был.

## 63.4 Пути мутации, обновляющие автора

`created_by` — `Create`, `Copy` (клон = копировщик, поля источника сбрасываются в `cloneNodeForCopy`).
`updated_by` — `Update` (полный PUT), `SetStatus`, `Move`, `UpdateAllowedHostsSnapshot` (привязка/
отвязка allowlist-хоста, §23 — бампает `updated_at`, поэтому и автора). Сигнатура порта
`NodeRepo.UpdateAllowedHostsSnapshot` расширена параметром `updatedBy`. `Delete` не применим (узла
не остаётся); `Replay`/`DryRun` не меняют строку узла — автора не трогают.

## 63.5 Вне scope

- Отдельная колонка/показ авторов для промежуточных правок (только «создал» и «последний изменил»).
- Бэкфилл авторов из аудита для узлов до 0026.
- FK на `users` и переживание переименования логина (хранится логин-строка на момент действия).
