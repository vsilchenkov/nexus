# 58. Поделиться узлом — ссылка на страницу узла + авто-переключение команды

Раздел вводит шаринг узла: кнопку «Поделиться», копирующую ссылку на страницу узла в UI, и
авто-переключение команды при открытии такой ссылки. Плюс аудит прав кнопок узла (кнопки-мутации
недоступны роли `viewer`). Развивает §18 (multi-tenancy, команды и team-switcher), §26 (RBAC),
§53 (кнопки шапки узла), §7.4 (страница узла).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md).

## 58.1 Проблема

Узел жёстко привязан к команде (`nodes.team_id`, §18), а «текущая команда» — состояние сессии в
Redis. `GET /api/nodes/{id}` team-scoped: при несовпадении команды узла и текущей команды сессии
отдаёт **404** (без утечки существования, §18). Поэтому если скинуть коллеге ссылку на страницу
узла из другой команды, у него страница не открылась бы — до §58 фронт на 404 просто редиректил на
список. Шаринга адреса узла в UI не было вовсе.

## 58.2 Кнопка «Поделиться» (п.1, п.4)

- Копирует в буфер обмена **ссылку на страницу узла в UI**: `${origin}/nodes/{id}`, где `origin` —
  адрес окна UI (`window.location.origin`), путь — стабильный team-независимый id-роут. Это НЕ боевой
  адрес вызова узла (`/api/v1/request/...`) — тот копируется отдельной кнопкой у «Полный адрес» (§28).
- Кнопка `ShareNodeButton` (`Share2` → `Check`/«Скопировано» ~1.5с), clipboard-логика — общий
  `lib/clipboard.ts` (переиспользуется и `CopyButton`).
- Доступна **всем ролям**, включая `viewer`: шаринг ссылки не мутирует данные, поэтому по роли
  **не гейтится** (в отличие от edit/copy).
- Размещение (п.4): в шапке страницы просмотра узла (`NodeDetail`, рядом с «Обновить») **и** в шапке
  действий формы правки (`NodeSettings`, только при редактировании — у нового узла ещё нет `id`).
- i18n: `node.actions.share` в обеих локалях.

## 58.3 Резолвер команды узла

Чтобы авто-переключиться на команду узла, фронту нужно узнать её **до** загрузки самого узла
(team-scoped `GET` вернул бы 404). Отдельный лёгкий read-endpoint:

`GET /api/nodes/{id}/team` (session-cookie, любая роль):

```json
{ "team_id": "<uuid>", "team_slug": "alpha", "team_name": "Alpha" }
```

Логика (`NodeUsecase.ResolveTeam`): загрузить узел без team-скоупа → найти его команду среди членств
пользователя (`TeamRepo.ListUserTeams`). «Узла нет» **и** «пользователь не член команды узла» →
единый **404** (`ErrNodeNotFound`, no-leak, как у `Get`). Только session-cookie
(`RequireSessionOnly`): API-токены однокомандные и команду не переключают.

## 58.4 Авто-переключение команды и «Узел не доступен» (п.2, п.3)

Хук `useEnsureNodeTeam(id)` возвращает статус `loading | switching | ready | unavailable`:

- резолвит команду узла (`GET /nodes/:id/team`);
- если команда узла ≠ текущей команде сессии — **один раз** на открытие узла вызывает
  `POST /api/me/switch-team` (guard по `id`: ручные переключения команды в шапке пользователь делает
  осознанно — назад не откатываем). После переключения `useSwitchTeam` инвалидирует team-scoped кеш,
  `GET /api/me/teams` перечитывает `current_team_id`;
- **ready** залипает (`latchedId`): после первого достижения ручная смена команды на странице не
  сбрасывает UI в «loading» — детальная сама обработает 404 узла, форма правки покажет баннер
  `foreign_team` (§18) с сохранением правок;
- **unavailable** (резолвер вернул 404: узла нет или его команда пользователю недоступна) → сообщение
  **«Узел не доступен»** (`node.unavailable`), п.3.

`NodeDetail` и форма правки `NodeSettings` грузят узел только при статусе `ready` — иначе team-scoped
`GET` отдал бы 404 ещё до переключения.

## 58.5 Аудит прав кнопок узла (п.5)

Проверены все кнопки-действия узла на соответствие RBAC (§26). Кнопки изменения/копирования/удаления
уже были закрыты (`useRoleAtLeast("manager")` на фронте, `RequireManager`/`RequireAdmin` на бэке).

**Найдена и закрыта дыра — Replay:** `POST /logs/:id/replay` был в группе `authed` (доступен
`viewer`), а кнопка Replay в логах и в таблице неудач «Очереди» не гейтилась. Replay пере-отправляет
запрос на внешнюю цель — сайд-эффект, недопустимый для роли «только просмотр» (§7.4.1: viewer видит
кнопку disabled). Фикс:

- backend: маршрут перенесён в `authedManager` + `RequireSessionOnly()` (viewer → 403; API-токены
  реплеить не могут — для них логи только snapshot, §7.14). С [§87](87-operator-role.md) — группа
  `authedOperator`;
- frontend: кнопки Replay в `LogsTab` и `QueueTab` гейтятся `useRoleAtLeast("manager")` — для viewer
  **disabled** с tooltip «Нет прав» (`common.no_permission`). С §87 гейт опущен до
  `useRoleAtLeast("operator")`.

Матрица кнопок узла после аудита (столбец «Право» приведён к состоянию после
[§87](87-operator-role.md) — до него операторские строки были manager+/admin):

| Кнопка | Экран | Право |
|---|---|---|
| Поделиться, Обновить | NodeDetail | любая роль |
| Тестовый запрос, Копировать, Изменить | NodeDetail | manager+ |
| Новый узел | Overview | manager+ |
| Перенести | Overview | admin |
| Сохранить, Удалить, форма целиком | NodeSettings | manager+ (форма редиректит viewer) |
| Replay (логи, неудачи очереди) | LogsTab / QueueTab | operator+ (viewer — disabled) |
| Живая очередь (pending, purge) | QueueTab | operator+ |
| Пауза / Отключить / Возобновить | QueueTab | operator+ |
| Снять защиту (breaker) | QueueTab | operator+ |
| Копирование значений (Config), метрики | NodeDetail | read-only, любая роль |

## 58.6 Неочевидности

- **Почему отдельный резолвер, а не «отдать узел кросс-командно»**: детальная страница узла тянет
  team-scoped данные (логи, метрики, CH-БД per team) — они всё равно требуют, чтобы текущая команда
  совпадала с командой узла. Поэтому переключаем сессию, а не ослабляем `Get`.
- **Ссылка на `/nodes/{id}`, а не на путь узла**: `id` (UUID) глобально уникален и team-независим;
  путь уникален лишь в пределах команды (`UNIQUE(team_id, path)`, §18).
- **Молчаливое переключение**: явного тоста нет — team-switcher в шапке сам показывает новую текущую
  команду; п.2 требует именно авто-переключение.
