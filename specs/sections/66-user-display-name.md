# 66. Отображаемое имя пользователя

Раздел добавляет пользователю обязательное поле **«Имя»** (display name) и переводит интерфейс на
показ имени вместо логина. Логин остаётся идентификатором входа и виден на административных
экранах вторичной строкой. Развивает §7.1/§7.9 (пользователи), §26 (аудит/актор), §63 (автор узла).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md) (§4.46).

## 66.1 Модель данных

Колонка в `users` (миграция 0028):

```sql
ALTER TABLE users ADD COLUMN name VARCHAR(255) NOT NULL DEFAULT '';
UPDATE users SET name = login;   -- разовый backfill
```

- **Backfill `name = login`** — существующие пользователи получают имя, равное логину;
  администратор затем правит имена вручную (Settings → Users).
- Обязательность — на уровне API (`binding:"required,min=1,max=255"` в create/update);
  в хранилище страховка `COALESCE(NULLIF(name,''), login)` для внутренних вызовов без имени
  (bootstrap admin).
- FK/уникальности нет: имя — представление, не идентификатор; тёзки допустимы.

## 66.2 API

- `POST /api/users`, `PUT /api/users/{id}` — поле `name` **обязательно** (создание и изменение).
- `userResponse`, `meResponse` (`/api/auth/login`, `/api/auth/me`), `teamMemberResponse`
  (`GET /api/teams/{id}/members`, обогащение JOIN'ом из `users`) отдают `name`.
- Поиск `GET /api/users?search=` — ILIKE по `login`, `email` **и `name`**.

## 66.3 Подпись автора и аудит (снапшоты)

- `domain.Session` несёт `Name` (пишется при логине); `Session.DisplayName()` = имя с фолбэком на
  логин. `Actor.UserLogin` заполняется `DisplayName()` — все снапшоты автора
  (`nodes.created_by/updated_by` §63, `user_audit.user_login`) с этого раздела пишутся **именем**.
- **Почему снапшот, а не резолв на чтении:** список пользователей admin-only (viewer/manager не
  смогли бы отобразить имя автора), пользователь может быть удалён; снапшот же согласован с датой
  действия. Старые записи остаются с логином — на момент миграции он равен имени, расхождения нет.
- Сессии, созданные до деплоя, поля `Name` не несут → до следующего входа подписи фолбэчат на логин.
  Активная сессия переименованного пользователя несёт старое имя до перелогина (осознанно);
  след переименования — в аудите `user.update`: `details.name` + `details.prev_name`.

## 66.4 UI

- **Сайдбар-чип** текущего пользователя — имя (инициал аватара от имени).
- **Settings → Users** — имя основное, логин вторичной строкой (моно; логин — кредентиал, админ
  обязан его видеть); поле «Имя» в диалоге создания/правки (обязательное, первым); заголовки
  диалогов и подтверждение удаления — по имени; плейсхолдер поиска упоминает имя.
- **Teams → Участники** — имя основное, логин вторичной строкой; select кандидатов — «Имя (логин)»
  (различение тёзок).
- **Автор узла (§63) и журнал аудита** — выводят содержимое снапшота: новые записи — имя, старые —
  логин. Правок рендера не требуют.
- Страница логина — без изменений: вход по логину.

## 66.5 Вне scope

- Self-service смена собственного имени (правит только admin).
- Бэкфилл имени в исторические снапшоты (created_by/аудит) при переименовании пользователя.
- Уникальность имени, транслитерация, аватары.
