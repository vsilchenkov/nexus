# 117. Переход к узлу из «Отказов»

Раздел даёт журналу отказов (§94) ссылку на узел: у отказов, причина которых относится к
существующему узлу («узел выключен», «метод запрещён», «нет авторизации», «адрес запрещён» и т. п.),
в строке таблицы и в карточке появляется переход на страницу узла. Попутно закрывается утечка: путь
отказа хранил секрет токена Telegram-бота в открытом виде.

Развивает [§94](94-rejected-requests.md) (журнал отказов), [§78](78-node-url-and-log-counters.md) и
[§100](100-click-targets.md) (адрес узла, кликабельные цели), [§79](79-failed-unit-node-tab-metrics.md)
(ссылка, а не кнопка), [§101](101-team-node-identity.md) (узел другой команды, §101.10),
[§39](39-path-passthrough.md) (хвост passthrough-адреса), [§109.6](109-sender-restart-resilience.md) и
[§95](95-log-secret-masking.md) (маскирование токенов ботов), [§74](74-safe-rollback.md) (аддитивные
миграции).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md). Миграции **0044–0046**. Новых ключей
`config.yml` нет. Выкатываются Receiver (пишет узел) и Web (отдаёт и показывает); **сначала Receiver**
(DEPLOYMENT §9.1.11): пока работает старый, он пишет в новые группы путь без маски и без узла.

---

## 117.1 Повод

- Оператор видит в «Отказах» строку «404 узел выключен · POST orders/create · 120 запросов» и
  должен сам искать этот узел в списке, хотя шина знала его в момент отказа. Ссылка на узел в
  карточке была только у подсказки «похожий путь» для настоящего 404 (§94.6).
- **Путь адреса ≠ путь узла.** Группа отказа ключуется путём из URL (§94.3), а не путём узла:
  - у passthrough-узла (§39) в пути остаётся хвост запроса (`tg/bot42:…/sendMessage`, узел — `tg`);
  - legacy-адрес `/api/v1/request/a/b` в «чтении B» резолвится в узел `a/b` команды default, а
    группа записывается как «команда `a`, путь `b`»;
  - узел могли переименовать или перенести после отказа.

  Поэтому сопоставить группу с узлом по пути на чтении (как делает страница Kafka, §101.10) нельзя:
  такое сопоставление промахивается ровно в перечисленных случаях.
- **Секрет в журнале.** Путь группы и сэмпла (`node_path`, `raw_path`) писался как пришёл, без
  `sensitive.MaskBotTokens`, хотя во всех остальных местах (лог, Sentry, метки) токен бота
  маскируется (§109.6). У passthrough-узла Telegram секрет `bot<id>:<secret>` оказывался в
  PostgreSQL, в интерфейсе «Отказов» и в CSV-выгрузке — то есть у любого оператора.

## 117.2 Какие отказы относятся к узлу

Узел известен, если Receiver успел его разрезолвить до отказа (наблюдатель резолва §101.3 вызван):

| Причина | Когда | Узел |
|---|---|---|
| `node_disabled` | узел выключен (для клиента — 404) | есть |
| `method_not_allowed` | метод не разрешён узлу | есть |
| `method_not_allowed` | не-POST на `/callback/` (до резолва) | нет |
| `unauthorized` | входящая авторизация узла (§41), подпись вебхука | есть |
| `url_not_allowed` | адрес вне списка разрешённых (`url_mode = from_request`) | есть |
| `bad_request` | нет/неверный URL-параметр, callback не разрешён, шаблон ответа §83 не собрался | есть |
| `body_too_large` | sync-запрос к узлу на паузе тяжелее async-лимита (§97) | есть |
| `node_not_found` | узел есть, но адрес не того типа: legacy `/request/` к не-sync узлу, async-адрес у узла без async-входа (§82.3), pull-узел по короткому адресу | есть |
| `node_not_found` | такого узла нет | нет |
| `rate_limited`, пустой путь, 413/400/508 на адресе с методом в пути | до резолва | нет |
| 413/400/508 на коротком адресе §78.1 | резолв выполнен раньше | есть |

## 117.3 Узел фиксируется в момент отказа

- Наблюдатель резолва (`RouteInput.OnNodeResolved`, параметр `NodeRootMethod`) получает структуру
  `ResolvedNode{TeamSlug, Path, ID}` вместо пары строк. Handler кладёт ID узла в контекст запроса
  под отдельным ключом (в метки Prometheus он не попадает — у них ограниченная кардинальность и
  своя семантика).
- Журнальный middleware переносит ID в наблюдение (`Sample.NodeID`), агрегатор группы держит
  последний непустой, писатель делает UPSERT:
  `node_id = COALESCE(EXCLUDED.node_id, rejected_groups.node_id)`. ID узла **не входит** в
  естественный ключ группы — иначе переименование узла или повторное создание с тем же путём
  дробили бы одну проблему клиента на несколько групп.
- Группы, накопленные до §117, получают узел при следующем отказе той же группы. Узнать узел задним
  числом по пути не пытаемся — по причинам из 117.1 это давало бы неверные ссылки.

## 117.4 Модель данных

- `0044_rejected_mask_bot_tokens` — удаляет группы и сэмплы, чей путь содержит немаскированный
  токен бота (регулярное выражение по форме `bot<цифры>:<base64url не короче 20>`; клиенты и сэмплы
  группы уходят каскадом). Маскировать на месте нельзя: две группы одного бота с разными секретами
  после маскирования совпали бы по уникальному ключу. `down` ничего не делает — удалённое не
  восстановить, а возвращать секреты незачем.
- `0046_rejected_mask_bot_tokens_team_slug` — то же для слога команды (найдено ревизией перед
  выпуском 1.42.0): код до §117 резал адрес на слог и путь без маски, и токен в ПЕРВОМ сегменте
  короткой формы (`/api/v1/request/bot<id>:<secret>/sendMessage`) оседал в `team_slug`. Новая
  миграция, а не правка 0044 — та уже применена на стендах. `down` ничего не делает.
- `0045_rejected_node_id` — `rejected_groups.node_id UUID NULL`, без внешнего ключа: узел удаляют, а
  его отказы остаются в журнале до срока хранения. Аддитивна (§74.2): старый Receiver колонку не
  пишет, старый Web её не читает. `down` удаляет колонку.

## 117.5 API

`GET /api/rejected` и `GET /api/rejected/{id}` (поле `group`) отдают у группы:

- `node` — `{id, path, status, team_slug, team_name}` узла, если он сохранён и существует. Путь и
  статус — **текущие** (из `nodes`), поэтому переименование и смена статуса после отказа ссылку не
  ломают;
- `node_deleted: true` — узел был сохранён, но его уже нет.

Нет ни того, ни другого — отказ к узлу не относится (или группа накоплена до §117 и с тех пор не
повторялась). CSV-выгрузка получает последнюю колонку `node` (текущий путь узла; `(deleted)` — узел удалён; пусто —
отказ к узлу не относится). Имя не `node_path`: так уже называется колонка пути адреса.

## 117.6 Интерфейс

```text
ПРИЧИНА             АДРЕС                            ЗАПРОСОВ
404 узел выключен   POST orders/create     ↗ узел         120
401 нет авторизации POST tg/bot42:***/send ↗ узел          15
404 узла нет        POST orders/creat                       3   ← узла нет — ссылки нет

Карточка отказа:
┌ orders/create ───────────────────────────── [⧉] [×] ┐
│ POST · 404 узел выключен · Склад                    │
│ ┌ Узел ───────────────────────────────────────────┐ │
│ │ orders/create · Склад · ● выключен               │ │
│ │ ↗ Открыть узел    ↗ Включить (вкладка «Очередь») │ │
│ └─────────────────────────────────────────────────┘ │
│ КЛИЕНТЫ …   ПОСЛЕДНИЕ ЗАПРОСЫ …                     │
└─────────────────────────────────────────────────────┘
```

- **Строка таблицы.** После адреса — короткая ссылка «↗ узел» прямо на страницу узла, без открытия
  карточки. Это настоящая ссылка (`<a href="/nodes/<id>">`, §79/§100): Ctrl+клик, средняя кнопка и
  «Открыть в новой вкладке» работают. Строка целиком остаётся растянутой ссылкой на карточку, ссылка
  на узел стоит поверх неё (`ABOVE_STRETCH`) соседним элементом, а не внутри ссылки строки.
- **Карточка.** Блок «Узел»: текущий путь, команда, статус; «Открыть узел» и — когда узел сейчас
  **выключен** — «Включить» на вкладку «Очередь» (`?tab=queue`), где живёт смена статуса (§35.4,
  роль operator+ — та же, что видит «Отказы»). Решение показывать «Включить» принимается по
  текущему статусу узла, а не по причине отказа: узел могли включить после отказа.
- **Узел удалён** — серое «узел удалён» без ссылки и в строке, и в карточке.
- **Узел другой команды.** Ссылка не несёт `?team=`: страница узла сама переключает команду сессии,
  если пользователь в ней состоит (§101.10); иначе показывает «Узел не доступен» — так же, как
  ссылки со страницы Kafka. Оператор и менеджер видят только отказы своей команды, и узел **чужой**
  команды им не показывается вовсе (`node` в ответе нет): группа своей команды указывает на чужой
  узел только при legacy-«чтении B» (`/request/a/b` → узел `a/b` команды default), и журнал не
  должен раскрывать путь, статус и название команды, к которой пользователь не относится — до §117
  журнал команды за её пределы не выходил. Администратор видит узел любой команды.

## 117.7 Маскирование токена бота

Путь группы (`node_path`) и путь сэмпла (`raw_path`) проходят через `sensitive.MaskBotTokens` до
записи: `tg/bot42:AAH…/sendMessage` → `tg/bot42:***/sendMessage`. Номер бота остаётся — по нему
видно, какой бот стучится. Группы одного бота с разными секретами (ротация токена) схлопываются в
одну — это правильно: для оператора это одна и та же проблема.

## 117.8 Границы и вне рамок

- Отказ до резолва узла (настоящий 404, 429, пустой путь, `/callback/` не тем методом) ссылки не
  получает — узла нет; для настоящего 404 по-прежнему работает подсказка «похожий путь» (§94.6).
- Группы до §117 получают узел только при повторном отказе; миграцией не дозаполняются.
- Узел другой команды: оператору и менеджеру не показывается; администратору показывается, а
  открывается, только если он участник этой команды (§101.10).
- Маскируется только форма токена Telegram-бота; другие секреты в пути URL (если клиент их туда
  кладёт) журнал не распознаёт — так же, как лог узла (§95).

## 117.9 Проверка

- Unit (Receiver): узел отказа попадает в наблюдение и агрегат; отказ до резолва — без узла; токен
  бота в пути группы и сэмпла маскируется (регрессия: красный на коде до §117).
- Integration: UPSERT сохраняет `node_id` и не затирает его пустым; чтение отдаёт текущий путь и
  статус узла и `node_deleted` после удаления; миграции 0044 и 0046 удаляют группы с токеном в пути
  и в слоге команды.
- Vitest: ссылка «↗ узел» только при `node`, правильный `href`; «Включить» только у выключенного;
  «узел удалён»; share-тест строки не сломан; ссылка не вложена в ссылку строки.
- Стенд: выключенный узел → запрос → строка со ссылкой, Ctrl+клик открывает узел в новой вкладке,
  карточка с «Включить»; passthrough-адрес с токеном → `bot<id>:***`; удалённый узел → «узел
  удалён».
