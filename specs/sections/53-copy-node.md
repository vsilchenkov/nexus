# 53. Копирование узла — кнопка «Скопировать узел»

Раздел вводит клонирование узла одним действием: полная копия конфигурации (включая креды) с новым
`path` в той же команде. Закрывает ручное перебивание десятков полей формы при создании похожего
узла. Развивает §3.3 (конфиг узла), §5.5 (шифрование кредов), §18 (`UNIQUE(team_id, path)`),
§23 (allowlist хостов), §26 (RBAC).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md).

## 53.1 Назначение и scope

- Копия создаётся **в той же команде**, что и источник. Кросс-командного копирования нет —
  для переноса между командами существует Move (§18).
- Доступ — **manager+** (как создание узла, §26). Маршрут в группе `authedManager`.
- Копирование **серверное**: креды никогда не возвращаются через API (§5.5, в `NodeResponse`
  только флаги `*_set`), поэтому клиентское «предзаполнить форму создания» не смогло бы перенести
  секреты. Серверный endpoint читает узел через usecase (креды уже расшифрованы адаптером),
  клонирует структуру в памяти и прогоняет стандартный Create-пайплайн — plaintext наружу не
  выходит, pg-адаптер перешифровывает при INSERT.

## 53.2 API

`POST /api/nodes/{id}/copy` (session-cookie, manager+):

```json
{ "path": "svc/orders-copy" }
```

Ответ `201 Created` + `NodeResponse` нового узла (креды, как всегда, не возвращаются — только
`auth_credentials_set` / `incoming_auth_credentials_set` / `rmq_password_set`).

Ошибки (единый `replyDomainError`, новых i18n-ключей не требуется):

| Код | Условие |
|---|---|
| 400 | невалидный `path` (доменная валидация, `code`+`field` для inline-подсветки, §28) / hard-limit узлов (§3.3) |
| 404 | источник не найден или принадлежит чужой команде (team-scope, без утечки существования) |
| 409 | `path` занят в команде (`UNIQUE(team_id, path)` → `node.already_exists`) |

## 53.3 Семантика клонирования

| Поле | Действие |
|---|---|
| `ID`, `CreatedAt`, `UpdatedAt` | сброс (назначают repo/БД) |
| `Path` | ← новый path из запроса |
| `Status` | **принудительно `paused`** — копия активного узла не должна молча начать принимать трафик |
| `TeamID` | команда источника (= current team вызывающего) |
| `URLAllowedHosts` | сброс, затем пересборка из склонированных ссылок (см. §53.4) |
| `ForwardHeaders` | глубокая копия (`slices.Clone`, не алиасит источник) |
| `AuthCredentials`, `IncomingAuthCredentials`, `RMQPassword` | копируются (plaintext в памяти → re-encrypt в pg-адаптере) |
| `ClickHouseTable`, `ClickHouseTemplateID`, retention | **копируются как есть** — несколько узлов могут писать в одну таблицу (§37 атрибутирует по `node_id`); `provisionTable` идемпотентен (`CREATE TABLE IF NOT EXISTS`), `normalizeCHTable` no-op на полном имени `db.table` |
| Всё остальное (методы, URL-режим, auth-типы и dynamic-поля, таймауты/ретраи, DLQ, логирование, `max_body_size*`, `rmq_*`/`pull_*`, `comment`) | копируется как есть |

Клон проходит **стандартный Create-пайплайн** (общий помощник `prepareNewNode`, извлечён из
`Create`): `SetDefaults` → `NormalizeForRootMethod` (§27.6) → `normalizeCHTable` → `Validate` →
self-reference (§32.2) → hard-limit (§3.3) → `provisionTable` (§19.5). Отдельной ветки валидации
для копии нет — копия не может «пронести» невалидную конфигурацию.

## 53.4 Клонирование allowlist-хостов

Снимок `url_allowed_hosts` — производный от каталога (§23), поэтому копируются **ссылки**
`node_allowed_hosts`, а снимок пересобирается: в той же UoW-транзакции, что и INSERT узла,
выполняется `ListByNode(source)` → `Link(clone, host)` для каждой → `UpdateAllowedHostsSnapshot`.
Без этого копия узла `url_mode=from_request` получила бы пустой allowlist (fail-closed) и
блокировала все запросы — то есть не была бы копией.

Fallback без UoW (CLI/unit-тесты; production-wiring всегда с UoW): узел создаётся, ссылки **не**
клонируются — Link + пересборка снимка вне транзакции могли бы разъехаться с созданием узла.
Пропуск виден на debug-уровне (§51.9).

## 53.5 Аудит

Новое действие **`node.copy`** (`domain.ActionNodeCopy`) — отдельное от `node.create`, чтобы в
журнале была видна провенансная связь. Записывается транзакционно с созданием узла. Details:

```json
{
  "source_node_id": "<uuid источника>",
  "source_path": "svc/orders",
  "path": "svc/orders-copy",
  "status": "paused",
  "allowed_hosts_cloned": 2
}
```

`node.copy` добавлено в фильтр действий на странице аудита.

## 53.6 UI

Кнопка **«Копировать»** в шапке страницы узла (`NodeDetail`, рядом с «Изменить», только manager+).
Открывает маленький диалог (по образцу Move-диалога Overview):

- единственное поле «Новый путь», префилл `<path-источника>-copy`;
- подсказка «Настройки и креды клонируются; копия создаётся на паузе»;
- клиентская валидация path (`validateNodePath`, зеркало доменной — кнопка неактивна при
  невалидном пути), серверные ошибки (409 занятый path и пр.) показываются локализованным
  сообщением в диалоге;
- успех → инвалидация списка узлов → переход на страницу копии `/nodes/{newId}`.

i18n: `node.actions.copy`, `node.copy.{title,new_path,hint,submit}` в обеих локалях.

## 53.7 Неочевидности

- **Кеш**: копия пишется в Redis-кеш write-through сразу (как Create) — Receiver видит paused-узел
  и отвечает по нему согласно §3.6, а не «узел не найден».
- **Pull-узлы (RabbitMQAsync)**: paused-копия не опрашивается Puller'ом (paused исключён из
  nodelister §27). Но после включения копии **два узла будут конкурировать за одну RMQ-очередь**
  (`rmq_queue` скопирован) — оператор должен сменить очередь или осознанно оставить конкуренцию.
- **Креды в ответе**: `201` возвращает `NodeResponse` с флагами `*_set=true` — пользователь видит,
  что секреты перенесены, не видя значений. В форме редактирования копии секретные поля пустые с
  плейсхолдером «оставьте пустым, чтобы сохранить текущее» (§5.5) — это ожидаемо.
- **Move остаётся admin-only, Copy — manager+**: копирование не пересекает границу команды, поэтому
  эскалации прав не требует.
