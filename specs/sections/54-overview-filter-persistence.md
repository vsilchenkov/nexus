# 54. Сохранение фильтров рабочего стола (Overview)

Раздел вводит переживание фильтров рабочего стола (`/`, Overview) при уходе на страницу узла и
возврате. Закрывает баг-репорт: выставленный фильтр сбрасывается при нажатии «Назад» в браузере или
кнопки «Узлы» в сайдбаре — оператор каждый раз перенабирает поиск. Развивает §7.3 (Overview),
§28.4 (период просмотра метрик), §44.B (дефолтный период «под себя»).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md).

## 54.1 Назначение и scope

**Проблема.** `search` / `method` / `statusFilter` / живой `period` жили в чистом `useState`
Overview. Компонент — дочерний `Outlet`, при переходе на `/nodes/:id` размонтируется, состояние
теряется безвозвратно. Кнопка «Узлы» — `NavLink to="/"` без query-строки: даже сохранение в URL
само по себе её кейс не закрывало бы.

**В scope** — четыре фильтра рабочего стола:

| Фильтр | Тип | Дефолт |
|---|---|---|
| Поиск по узлам | `string` | `""` |
| Корневой метод | `"" \| request \| requestAsync \| RabbitMQAsync` | `""` (все) |
| Статус | `all \| ok \| warn \| degraded \| err \| paused \| disabled` | `all` |
| Живой период метрик | `Period` (§28.4: пресет 1h..30d \| custom from/to) | `loadDefaultPeriod()` — звёздочка §44.B |

**Вне scope** (уже персистятся в `localStorage`, не трогаются): режим Таблица/Карточки
(`nexus.overview.view`, §7.3), пауза автообновления (`nexus.overview.autorefresh`, §44.C),
дефолтный период «звёздочка» (`nexus.overview.period`, §44.B). Серверное per-user хранение
фильтров (по образцу §49) — не вводится, см. §54.3.

## 54.2 Модель: URL — источник истины, storage — зеркало

Состояние фильтров **не дублируется в React-state**: оно производно от `useSearchParams()`
(конвенция §7 / `AuditLog`, фикс П12). Зеркало в `sessionStorage` добавляется только чтобы пережить
переход, теряющий query-строку.

Query-параметры страницы `/`:

| Параметр | Значение |
|---|---|
| `q` | строка поиска |
| `method` | `request` / `requestAsync` / `RabbitMQAsync` |
| `status` | `ok` / `warn` / `degraded` / `err` / `paused` / `disabled` |
| `range` | пресет периода `1h`/`3h`/`24h`/`7d`/`14d`/`30d` |
| `from` + `to` | произвольный период, RFC3339 |

Имена `range` / `from` / `to` — **намеренная симметрия с `periodParams()`** для `/api/metrics/*`
(те же значения и форматы). Коллизии с дип-линком логов узла (`/nodes/:id?tab=logs&from&to`, §47.4)
нет — другой маршрут.

**Правила сериализации:**

- В URL пишутся **только отличия от дефолта**. Все фильтры дефолтные → query-строка пуста, адрес
  остаётся чистым `/`.
- `range` приоритетнее `from`/`to`, если в URL пришло и то, и другое.
- Разбор толерантен к мусору: невалидное значение каждого параметра независимо откатывается к
  дефолту (`?status=banana&q=foo` → статус `all`, поиск `foo`), страница не падает.
- Чужие query-параметры при обновлении фильтров сохраняются — модуль владеет только своими ключами.

**Поведение по кейсам:**

| Кейс | Механизм |
|---|---|
| «Назад» браузера со страницы узла | URL с query восстанавливается браузером |
| F5 / дип-линк / ссылка коллеге | URL с query |
| Кнопка «Узлы» в сайдбаре (`to="/"`, query теряется) | URL пуст → восстановление из `sessionStorage` + `replace` |
| Клик «Узлы», когда уже на `/` с фильтрами | То же (ремоунта нет, `params` пустеют — эффект возвращает фильтры) |
| Ручная очистка всех фильтров | Всё-дефолт → ключ `sessionStorage` удаляется → восстанавливать нечего |
| Новая вкладка / перезапуск браузера | Чистый лист + период от звёздочки §44.B |

Все записи в историю — `replace`: перебор фильтров не засоряет Back-стек (конвенция `AuditLog`).

## 54.3 Почему sessionStorage

Прецеденты в проекте расходятся: §44.B выбрал `localStorage` (дефолтный период), §49 явно его
отверг в пользу PG (избранные команды переживают смену устройства). Для фильтров выбран
**`sessionStorage`**, тип хранилища вынесен в одну константу модуля:

- `localStorage` **вытеснил бы звёздочку §44.B**: сохранённый живой период восстанавливался бы
  всегда, и пользовательский дефолт перестал бы быть заметен. С `sessionStorage` новая сессия
  стартует с дефолтного периода — звёздочка сохраняет смысл.
- Фильтр — состояние сиюминутной задачи («смотрю почту»), а не настройка. «Прилипший» на недели
  фильтр даёт непонятно пустой список при следующем заходе.
- Вкладки независимы: фильтры одной вкладки не «воскресают» в другой.
- PG per-user (как §49) — оверкилл: фильтр не нужен на другом устройстве, а шаринг покрывается URL.

Ключ — `nexus.overview.filters`, значение — та же сериализованная query-строка (один сериализатор
на URL и storage; восстановление = `parse → serialize → setParams`, что заодно санитизирует мусор
из хранилища перед записью в адрес). Доступ к хранилищу толерантен к приватному режиму
(`try/catch`, как `saveDefaultPeriod`).

## 54.4 Неочевидности

- **Порядок «save → setParams» обязателен.** `saveFilters` вызывается синхронно в сеттере **до**
  `setParams`. Иначе при ручной очистке фильтров эффект восстановления в том же коммите увидел бы
  «URL пуст, а storage ещё непуст» и воскресил бы только что очищенный фильтр. При всё-дефолт
  сеттер делает `removeItem` — восстановление становится no-op, логика замкнута.
- **Дефолтный период не сериализуется** (§54.2) — отсюда нюанс шаринга: ссылка, отправленная с
  дефолтным периодом отправителя, откроется у получателя с **его** дефолтом (звёздочка §44.B у них
  может отличаться). Чтобы зафиксировать период в ссылке явно, нужно выбрать не-дефолтный пресет —
  тогда `range` в URL присутствует.
- **Поиск коммитится в URL с debounce ~300 мс** (локальный state инпута → таймер → URL + storage).
  Причина не косметическая: Safari троттлит `history.replaceState` (~100 вызовов / 30 с, дальше
  `SecurityError`) — запись на каждый keystroke реально упирается в лимит при быстром наборе.
  Побочно снимается спам в `/api/nodes` (queryKey `["nodes", search]` дёргал запрос на каждый
  символ). Внешнее изменение `q` (восстановление, «Назад») синхронизирует инпут, не затирая ввод
  пользователя, пришедший позже коммита.
- **Восстановление не ломает Back.** Клик «Узлы» — это push `/`, восстановление делает `replace`
  поверх него, поэтому «Назад» со списка ведёт на предыдущую страницу, а не на «голый `/`».
