# 108. Отмена изменения узла из журнала аудита

Раздел добавляет журналу аудита две возможности для администратора:

- **«Отменить изменение»** в строке `node.update`: вернуть поля узла к значениям «Было»;
- **подсветка неактуальных строк**: изменение, которое уже перебито, отменено или чей узел удалён,
  видно сразу, без сверки с карточкой узла.

Развивает [§7.13](07-web-ui.md) (журнал аудита, append-only), [§91](91-audit-scale-and-scope.md)
(выдача журнала, видимость глобальных записей админу), [§63](63-node-author.md) (автор изменения),
[§26](26-roles-access-control.md)/[§87](87-operator-role.md) (роли).

Карта реализации — [../IMPLEMENTATION.md](../IMPLEMENTATION.md). **Миграций нет, конфига нет,**
выкатывается только Web.

---

## 108.1 Повод и охват

Журнал показывает «Было / Стало» по каждому полю `node.update` — например, `status paused → enabled`,
`target_url …:8192 → …:8200`. Когда изменение оказалось ошибкой, вернуть значения можно было только
вручную через форму узла, переписывая их с экрана журнала. При разборе инцидента («кто-то поменял
адрес — верните как было») это медленно и чревато опечаткой.

**Что отменяется.** Только строки `node.update` — и полная правка узла (PUT), и смена статуса
(PATCH, кнопки «Пауза»/«Отключить»): обе пишут одинаковый diff `{поле: {before, after}}`. Сама
отмена пишется **новой** строкой `node.revert` того же формата, и её тоже можно отменить — это
повтор отменённого изменения.

**Кто.** Только глобальная роль `admin`, только через браузерную сессию: API-токен (даже с ролью
admin) кнопок и подсветки не получает, эндпоинты отмены закрыты `RequireSessionOnly`. Для
`operator` и `manager` журнал выглядит как прежде.

**Журнал остаётся append-only** (§7.13 «Безопасность»): ни отмена, ни подсветка записи журнала не
меняют. Неактуальность вычисляется на лету при каждой выдаче.

## 108.2 Какие поля можно вернуть

Отмена работает только с тем, что записано в строке журнала. `diffNodes` пишет 24 скалярных поля
со значениями «до/после»:

`path`, `target_url`, `url_mode`, `auth_type`, `incoming_auth_type`, `status`, `timeout_ms`,
`retry_count`, `webhook_signature_header`, `webhook_signature_prefix`, `external_table`,
`circuit_breaker_threshold`, `circuit_breaker_cooldown_sec`, `sse_decline`,
`breaker_ignore_timeouts`, и только у pull-узлов (`RabbitMQAsync`) — `rmq_host`, `rmq_port`,
`rmq_vhost`, `rmq_user`, `rmq_queue`, `rmq_use_tls`, `pull_interval_sec`, `pull_batch_size`,
`pull_prefetch`.

Список полей живёт в одном месте — реестре полей узла (`nodeFieldRegistry`). По нему строится и
diff аудита, и отмена, поэтому поле, добавленное в аудит, сразу становится отменяемым, а
разъехаться эти два списка не могут.

**Не восстанавливаются:**

- **креды** (`auth_credentials`, `incoming_auth_credentials`, `rmq_password`) — в журнал пишется
  только факт `"changed"`, значения там нет и не будет (§7.13: «значения паролей и токенов — только
  факт изменения»);
- **шаблон ответа приёма** (`async_ack_spec`, §83) — в журнале его сводка с телом, обрезанным до
  500 символов; восстановить из неё спеку нельзя. В неактуальность строки поле при этом
  учитывается: сводка текущей спеки сравнивается со «Стало»;
- **поля, которых нет в diff вовсе**: `root_method`, методы, комментарий, группа, настройки
  логирования, CH-таблица, заголовки и др. Отмена их не трогает. Строка, в которой изменились
  только такие поля, выглядит «без изменений», и отменять в ней нечего.

Значения в JSONB читаются как `float64`/`bool`/`string`; поле восстанавливается разбором
JSON-значения в его настоящий тип (`int32`, перечисление, `bool`). Нецелое или вышедшее за `int32`
число, `null` и значение чужого типа отклоняются — такое поле помечается `unrecoverable`.

## 108.3 Статус поля и состояние строки

Каждое поле строки сравнивается с текущим узлом:

| Статус | Условие | В диалоге отмены |
|---|---|---|
| `actual` | сейчас == «Стало» | отмечено по умолчанию |
| `overwritten` | сейчас ≠ «Стало» и ≠ «Было» — поле перебито позже | предупреждение, не отмечено |
| `already` | сейчас == «Было» — отменять нечего | без галки, «уже такое значение» |
| `inapplicable` | поле не относится к типу узла (`rmq_*`/`pull_*` у не-pull) | без галки |
| `unrecoverable` | `async_ack_spec`, нечитаемое значение | без галки |
| `secret` | `"changed"` у кредов | информационная строка |

`inapplicable` нужен потому, что у узла не pull-типа репозиторий пишет `rmq_*`/`pull_*` как NULL:
значение из журнала туда просто не сохранится, а сравнение с нулём давало бы ложную
«неактуальность».

**Предупреждение `credentials`.** Если в той же строке креды помечены `"changed"`, связанное поле
получает предупреждение и не отмечено по умолчанию: вернуть `auth_type` можно, а креды — нет, и
узел окажется с типом авторизации от одного состояния и кредами от другого. Связи:
`auth_type` ↔ `auth_credentials`; `incoming_auth_type`, `webhook_signature_*` ↔
`incoming_auth_credentials`; `rmq_*` ↔ `rmq_password`.

**Состояние строки:**

- `gone` — узла больше нет;
- `none` — сравнивать нечего (только креды или неприменимые поля) — без подсветки и без кнопки;
- `stale` — хотя бы одно сравнимое поле сейчас ≠ «Стало»;
- `actual` — иначе.

Неактуальность сравнивает **значения, а не историю**: после цепочки A→B, B→A, A→B первая строка
снова актуальна — узел действительно в том состоянии, которое она описывает.

Кнопка отмены показывается, когда узел жив и есть хотя бы одно поле `actual` или `overwritten`.

## 108.4 Применение: какой путь сохранения

Отмена накладывает выбранные значения «Было» на **копию текущего узла** — все остальные поля,
креды и снимок allowlist остаются как есть — и сохраняет её тем же конвейером, что форма узла:

1. `SetDefaults` → `NormalizeForRootMethod` → нормализация CH-таблицы → `Validate` → проверки
   чужой таблицы (§70.6) и самоссылки (§32.2);
2. **проверка «значения удержались»**: каждое выбранное поле после шага 1 обязано совпасть с
   «Было». Нормализация может молча сбросить значение — например, `sse_decline` у узла с входящим
   методом POST (§107.2) или `rmq_port = 0`, который `SetDefaults` заменит портом по умолчанию. Тогда
   отмена отклоняется целиком (`audit.revert.not_held` со списком полей), узел не меняется;
3. запись узла и строки аудита в одной транзакции (UoW), затем кеш Redis и сигнал Receiver'у (§57).

**Только статус — облегчённый путь.** Если выбрано одно поле `status`, отмена идёт путём кнопок
«Пауза»/«Отключить» (`SetStatus`): без полной валидации. Иначе старый узел, не проходящий
сегодняшние правила (например, §69.2), нельзя было бы снять с паузы отменой, хотя кнопкой можно.

**Предпросмотр** выполняет шаги 1–2 без записи для выбора по умолчанию и показывает, что не
удержится и какая ошибка валидации ждёт, до нажатия кнопки.

## 108.5 Конфликт: узел изменился после предпросмотра

Предпросмотр отдаёт `updated_at` узла, применение присылает его обратно (`expected_updated_at`).
Не совпало — `409 audit.revert.conflict`, узел не меняется, диалог перечитывает предпросмотр.

- Строка возвращается **как пришла**: `Date` в JavaScript хранит миллисекунды, PostgreSQL —
  микросекунды, и `toISOString()` давал бы 409 всегда.
- `updated_at` поднимают и привязка хоста (§23), и перенос (§58) — отмена после них тоже получит
  409. Это безопасно: предпросмотр просто перечитывается.
- **Граница защиты:** проверка идёт перед записью, а не в самом `UPDATE`: окно между ними
  остаётся, как у двух одновременных сохранений формы сегодня. Атомарной оптимистичной
  блокировки узлов в шине нет (вне рамок, §108.9).

## 108.6 Запись `node.revert`

- `action = "node.revert"`, `target_type = "node"`, `target_id` — id узла.
- `details` — diff в формате `node.update` (`{поле: {before, after}}`, где `before` — значение до
  отмены) плюс `reverted_from` (id отменённой строки) и `reverted_from_at` (её время, UTC).
- `team_id` строки — **команда узла**, а не текущая команда админа: иначе команда узла отмены в
  своём журнале не увидела бы. Автор (`updated_by`, §63) — админ.
- Отмена отменённого — обычная отмена строки `node.revert`: в ней `before`/`after` те же, что у
  любой правки.

## 108.7 API

Оба эндпоинта: `authedAdmin` + `RequireSessionOnly`. Путь `/audit/revert/:id`, а не
`/audit/:id/revert`, — чтобы параметр не стоял рядом со статическими `count` и `export.csv`.

**`GET /api/audit/revert/{id}`** — предпросмотр:

```json
{
  "entry": {"id": "…", "action": "node.update", "created_at": "…", "user_login": "…"},
  "node": {"id": "…", "path": "…", "team_id": "…", "updated_at": "2026-09-24T10:00:00.123456Z"},
  "state": "stale",
  "moved": false,
  "fields": [
    {"name": "target_url", "before": "…:8192", "after": "…:8200", "current": "…:8300",
     "status": "overwritten", "warning": ""}
  ],
  "dry_run": {"code": "", "field": "", "not_held": [], "error": ""}
}
```

`dry_run.error` — перевод `code` на языке запроса (запасной текст для клиента). Внутренняя ошибка
пробного прогона (например, сбой ClickHouse при проверке таблицы) предпросмотр не роняет:
`code = error.internal`, подробности — только в логе. Занятость пути пробный прогон не видит —
её проверяет запись (409).

`node = null`, если узел удалён. `moved` — строка писалась в другой команде, чем та, где узел
сейчас (узел переносили).

**`POST /api/audit/revert/{id}`** с `{"fields": ["target_url"], "expected_updated_at": "…"}` →
`204`.

| Ошибка | Ответ |
|---|---|
| запись не найдена, не UUID | 404 `audit.revert.entry_not_found` |
| действие не отменяется | 400 `audit.revert.not_revertible` |
| поле не отменяемо или неизвестно | 400 `audit.revert.field_invalid` |
| узел изменился | 409 `audit.revert.conflict` |
| значения не удержались | 400 `audit.revert.not_held` + `fields` |
| узел удалён | 404 `audit.revert.node_gone` |
| путь занят другим узлом | 409 (код узла) |
| валидация узла | 400 `{code, field}` (коды формы узла) |

**`GET /api/audit`** — у элементов `node.update`/`node.revert` для admin-сессии появляется поле
`revert`: `{"state": "stale", "revertible": true, "overwritten": {"status": "enabled"}}`
(`overwritten` — текущие значения перебитых полей, для подсказки). Считается одним запросом узлов
на страницу выдачи. Ошибка расчёта не роняет выдачу: список отдаётся без поля `revert`
(fail-open), в лог — предупреждение. CSV-выгрузка не меняется.

## 108.8 Интерфейс

Последняя колонка таблицы журнала — только у admin:

```text
┌─────────────┬──────────┬────────────────┬─────────────┬──────┬──────────────────────────────────────┬───┐
│ Когда       │ Кто      │ Действие       │ Цель        │ IP   │ Детали     Было          Стало       │   │
├─────────────┼──────────┼────────────────┼─────────────┼──────┼──────────────────────────────────────┼───┤
│ 24.09 12:05 │ Админ    │ [node.revert]  │ node/ea9435 │ …    │ ↺ отмена записи от 23.09 18:36       │ ↺ │
│             │          │                │             │      │ status      enabled      paused      │   │
├─────────────┼──────────┼────────────────┼─────────────┼──────┼──────────────────────────────────────┼───┤
│░23.09 18:36░│░Сильченко│ [node.update]  │ node/ea9435 │ …    │ status      paused   ~~enabled~~ ⓘ   │ ↺ │
│░(фон warn) ░│░         │ [неактуально]  │             │      │ target_url  …:8192   …:8200          │   │
├─────────────┼──────────┼────────────────┼─────────────┼──────┼──────────────────────────────────────┼───┤
│░23.09 17:00░│░Иванов   │ [node.update]  │ node/9f8e7d │ …    │ (diff приглушён)                     │   │
│░(фон warn) ░│          │ [узел удалён]  │             │      │                                      │   │
└─────────────┴──────────┴────────────────┴─────────────┴──────┴──────────────────────────────────────┴───┘
```

- ↺ — иконка-кнопка «Отменить изменение».
- Неактуальная строка — лёгкий фон `warn`, чип под действием («неактуально» / «узел удалён»),
  приглушённый diff. Прозрачность всей строки не используется: потускнела бы и кнопка.
- Перебитое поле: «Стало» зачёркнуто, подсказка — «сейчас: X».
- Строка `node.revert` показывает diff и вместо служебных ключей — «отмена записи от <дата>».
- `node.revert` есть в фильтре действий.

Диалог отмены:

```text
┌ Отменить изменение ───────────────────────────────────────────────── ✕ ┐
│ node.update · Сильченков Владимир · 23.09.2026 18:36:22                 │
│ Узел: /api/v1/support/it_upr-vika                                       │
│ ⚠ Узел перенесён в другую команду после этой записи      (если перенесён)│
│                                                                         │
│       Поле               Сейчас                   →  Станет             │
│ [x]   status             enabled                  →  paused             │
│ [ ]   target_url         …:8300 ⚠ изменено позже  →  …:8192             │
│ [ ]   auth_type          bearer ⚠ креды не вернутся → basic             │
│  —    timeout_ms         5000                        уже такое значение │
│  —    auth_credentials   секрет — в журнале не хранится                 │
│                                                                         │
│ ⚠ Проверка: sse_decline будет сброшено                                  │
│ ⓘ Отмена запишется в журнал новой строкой node.revert                   │
│                                        [Закрыть]  [Отменить изменения (1)]│
└─────────────────────────────────────────────────────────────────────────┘
```

После успеха обновляются журнал, счётчик и данные узла. 409 — сообщение «узел изменился» и
перечитанный предпросмотр; прочие ошибки — строкой в диалоге.

## 108.9 Вне рамок

- **Отмена других действий** (справочники, `node.create`/`node.delete`, пользователи, команды):
  в их записях нет значений «Было». Удалённый узел по журналу не восстановить — строка удаления
  хранит только путь и имя таблицы.
- **Восстановление кредов и `async_ack_spec`** — значений в журнале нет (§108.2).
- **Расширение состава diff** полями `comment`, `group_id`, логированием, CH, `root_method`.
  Изменение аддитивное и действовало бы только для новых строк — отдельное решение.
- **Атомарная оптимистичная блокировка** `UPDATE … WHERE updated_at = $n` для всех сохранений
  узла (§108.5).
- **Ссылка на отменившую строку** в отменённой («отменено админом N в …»): поиск по
  `details->>'reverted_from'` без индекса на каждой странице выдачи дорог, а состояние
  `stale` уже говорит главное.
